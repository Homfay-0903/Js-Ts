## 1. OBJ 文件的上传、处理、解析

### 问题是什么

需求要求支持两种 OBJ 模型文件导入：
- **体态模型**：文件名格式 `BODY-姓名-性别-年龄-体重-就诊号码.obj`
- **足压模型**：文件名格式 `FEET-姓名-性别-年龄-体重-就诊号码.obj`

系统需要：
1. 校验文件名格式是否合规
2. 从文件名中解析出患者基础信息（姓名、性别、年龄、体重、就诊号）
3. 将文件转为可被 Three.js 加载的本地 URL
4. 全程不依赖后端接口（前端纯本地处理）

### 如何解决的

#### 文件名格式校验

采用正则表达式严格校验文件名结构：

```javascript
// src/pages/model-import/Index.vue
const pattern = this.currentModelType === 'BODY'
    ? /^BODY-[^-]+-[^-]+-\d+-\d+-[^-]+\.obj$/i
    : /^FEET-[^-]+-[^-]+-\d+-\d+-[^-]+\.obj$/i

if (!pattern.test(file.name)) {
    this.validationStatus = 'error'
    this.validationMessage = '格式错误'
    this.$message.error('文件名格式错误！请按命名规范重新命名文件')
    return
}
```

正则要点：
- `[^-]+` 匹配不含连字符的任意字符（姓名、性别、就诊号）
- `\d+` 匹配纯数字（年龄、体重）
- `i` 标志忽略大小写

#### 文件名信息解析

通过 `split('-')` 拆分文件名各段，映射为结构化对象：

```javascript
const fileName = this.selectedFile.name
const parts = fileName.replace('.obj', '').split('-')

const memberInfo = {
    name: parts[1],           // 姓名
    gender: parts[2],          // 性别
    age: parseInt(parts[3], 10),    // 年龄
    weight: parseFloat(parts[4]),   // 体重
    visitNumber: parts[5]      // 就诊号
}
```

#### 文件转本地 URL

使用浏览器原生 `URL.createObjectURL()` 将 File 对象转为 Blob URL，供 Three.js OBJLoader 直接加载：

```javascript
const modelUrl = URL.createObjectURL(this.selectedFile)
this.modelUrl = modelUrl
```

这个 URL 在当前页面会话内有效，OBJLoader 可像加载远程 URL 一样加载它，无需上传到服务器。

#### 上传进度模拟

由于是纯前端本地处理，没有真实网络上传过程。为提供与原系统一致的用户体验，用 `setTimeout` 模拟分阶段进度（30% → 60% → 100%）：

```javascript
this.uploading = true
this.uploadProgress = 30
// ...解析文件名...
this.uploadProgress = 60
setTimeout(() => {
    const modelUrl = URL.createObjectURL(this.selectedFile)
    this.uploadProgress = 100
    this.uploading = false
    // 进入数据处理页
    this.currentView = 'process'
}, 800)
```

### 最终效果

- 用户选择 OBJ 文件后，系统实时校验文件名格式并给出「校验通过/格式错误」反馈
- 点击「开始导入」后，解析出患者信息，生成模型本地 URL，自动进入数据处理页
- 全程无后端依赖，文件不离开浏览器

## 2. 3D 模型页面展示与旋转/缩放交互

### 问题是什么

需要将 OBJ 模型在网页中渲染展示，并支持：
- 旋转查看（多视角）
- 缩放查看
- 模型自动居中、适配视口大小

### 如何解决的

#### Three.js 场景初始化

在 [ProcessPreview.vue](file:///c:/Users/Administrator/work/ve730-ve760/ve730-cms-frontend/src/components/model-import/ProcessPreview.vue) 中初始化标准 Three.js 渲染管线：

```javascript
initThree() {
    const container = this.$refs.modelContainer
    const width = container.clientWidth
    const height = container.clientHeight

    // 场景
    this.scene = new THREE.Scene()
    this.scene.background = new THREE.Color(0xf9fdff)

    // 透视相机
    this.camera = new THREE.PerspectiveCamera(45, width / height, 0.1, 1000)
    this.camera.position.set(0, 0, 5)

    // WebGL 渲染器
    this.renderer = new THREE.WebGLRenderer({ antialias: true })
    this.renderer.setSize(width, height)
    this.renderer.setPixelRatio(window.devicePixelRatio)
    container.appendChild(this.renderer.domElement)

    // 三点光照
    const ambientLight = new THREE.AmbientLight(0xffffff, 0.6)
    this.scene.add(ambientLight)
    const directionalLight = new THREE.DirectionalLight(0xffffff, 0.8)
    directionalLight.position.set(1, 1, 1)
    this.scene.add(directionalLight)
    const backLight = new THREE.DirectionalLight(0xffffff, 0.4)
    backLight.position.set(-1, 0.5, -1)
    this.scene.add(backLight)

    // OrbitControls 提供旋转/缩放交互
    this.controls = new OrbitControls(this.camera, this.renderer.domElement)
    this.controls.enableDamping = true
    this.controls.dampingFactor = 0.05
    this.controls.minDistance = 2
    this.controls.maxDistance = 10

    this.animate()
}
```

#### OBJ 模型加载

使用 Three.js 官方的 OBJLoader 加载模型：

```javascript
loadModel(url) {
    const loader = new OBJLoader()
    loader.load(
        url,
        (object) => {
            this.model = object
            this.centerModel(object)

            // 统一设置材质
            object.traverse((child) => {
                if (child.isMesh) {
                    child.material = new THREE.MeshStandardMaterial({
                        color: 0xe0f2fe,
                        roughness: 0.7,
                        metalness: 0.1
                    })
                }
            })

            this.scene.add(object)
        },
        null,
        (error) => {
            console.error('加载模型失败：', error)
            this.$message.error('模型加载失败')
        }
    )
}
```

#### 模型居中与自适应缩放

这是关键一步。OBJ 模型的原始坐标范围差异极大（体态模型高度可达 1700mm，足压模型约 224mm），必须统一缩放到视口合理范围：

```javascript
centerModel(object) {
    const box = new THREE.Box3().setFromObject(object)
    const center = box.getCenter(new THREE.Vector3())
    const size = box.getSize(new THREE.Vector3())

    const maxDim = Math.max(size.x, size.y, size.z)
    const scale = maxDim > 0 ? 2.5 / maxDim : 1

    // 关键：position 和 scale 必须同步应用
    // position = -center * scale，使模型中心移到原点
    object.position.x = -center.x * scale
    object.position.y = -center.y * scale
    object.position.z = -center.z * scale
    object.scale.set(scale, scale, scale)
}
```

**技术要点**：`position = -center * scale` 而非 `-center`。因为缩放是围绕原点进行的，必须先按缩放比例偏移中心点，才能让模型几何中心准确落在世界原点 (0,0,0)。

#### 渲染循环

```javascript
animate() {
    if (!this.renderer) return
    this.animationId = requestAnimationFrame(this.animate)
    if (this.controls) {
        this.controls.update()   // damping 阻尼更新
    }
    this.renderer.render(this.scene, this.camera)
}
```

### 最终效果

- OBJ 模型加载后自动居中显示，无论原始坐标范围多大都能适配视口
- 左键拖动旋转、滚轮缩放，带阻尼平滑效果
- 三点光照让模型立体感清晰

## 3. 跨浏览器标签页报告同步更新

### 问题是什么

用户可能同时打开多个浏览器标签页（例如一个在「模型导入」页生成报告，另一个在「扫描列表」页查看报告列表）。当 A 标签页新增/删除报告时，B 标签页的列表需要**自动刷新**，无需用户手动刷新页面。

### 如何解决的

#### 基于 localStorage + StorageEvent 的跨标签页通信

浏览器原生的 `storage` 事件天然支持跨标签页通信：当某个标签页修改 localStorage 时，**其他标签页**会收到 `StorageEvent`（注意：触发修改的当前标签页不会收到自己的 storage 事件）。

#### 存储服务封装

在 [reportStorage.js](file:///c:/Users/Administrator/work/ve730-ve760/ve730-cms-frontend/src/utils/reportStorage.js) 中封装存储与监听：

```javascript
const STORAGE_KEY = 've760_model_import_reports'

// 读取
export function getReports() {
    const data = localStorage.getItem(STORAGE_KEY)
    return data ? JSON.parse(data) : []
}

// 写入（会触发其他标签页的 storage 事件）
export function saveReports(reports) {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(reports))
}

// 新增/更新报告
export function addReport(report) {
    const reports = getReports()
    const index = reports.findIndex(item => item.scanId === report.scanId)
    if (index > -1) {
        reports[index] = { ...reports[index], ...report }
    } else {
        reports.unshift(report)
    }
    saveReports(reports)
    return reports
}

// 删除
export function deleteReport(scanId) {
    const reports = getReports().filter(item => item.scanId !== scanId)
    saveReports(reports)
    return reports
}

// 生成唯一 scanId
export function generateScanId() {
    return 'mi-' + Date.now() + '-' + Math.random().toString(36).substr(2, 9)
}

// 注册跨标签页变化监听
export function onReportsChange(callback) {
    const handler = (event) => {
        if (event.key === STORAGE_KEY) {
            callback(getReports())
        }
    }
    window.addEventListener('storage', handler)
    // 返回取消监听函数，便于组件销毁时清理
    return () => window.removeEventListener('storage', handler)
}
```

#### 列表页订阅

在 [ScanList.vue](file:///c:/Users/Administrator/work/ve730-ve760/ve730-cms-frontend/src/pages/home/ScanList.vue) 的 mounted 中注册监听，beforeDestroy 中取消：

```javascript
mounted() {
    // 监听 localStorage 变化，实现多标签页同步
    this.unwatchReports = onReportsChange((reports) => {
        this.getScanList()   // 重新拉取并合并本地报告
    })
},
beforeDestroy() {
    if (this.unwatchReports) {
        this.unwatchReports()
    }
}
```

#### 列表数据合并

`getScanList()` 方法会将后端扫描数据与本地存储报告合并展示：

```javascript
// 本地报告转为列表项格式
return getReports().map(item => ({
    ...item,
    isLocalReport: true   // 标记为本地报告，删除时走本地逻辑
}))
```

### 最终效果

- A 标签页生成新报告 → B 标签页列表自动出现新条目
- A 标签页删除报告 → B 标签页列表自动移除对应条目
- 全程无轮询、无 WebSocket，纯浏览器原生能力，零后端依赖

## 4. 红色控制点拖动与指标实时联动（核心难点）

### 问题是什么

这是整个模型模块**最复杂、迭代次数最多**的功能。需求：
- 在 3D 模型上显示红色球形控制点（关键解剖点位）
- 用户用鼠标按住红色控制点拖动
- 拖动过程中，左侧指标面板的测量值（角度/长度）**实时变化**
- 拖动有约束：控制点只能在以另一个锚点为圆心、初始距离为半径的**球面**上移动（模拟关节旋转）

这个功能在 2D 模型（SVG）中已实现（见 `model-edit.vue`），需要迁移到 3D 场景。

### 迭代尝试（完整历程）

#### 尝试一：直接在 canvas 上绑定 mousedown

**方案**：OrbitControls 绑定到 canvas，同时我们自己也在 canvas 上 `addEventListener('mousedown', handleMouseDown)`。

**结果**：❌ 拖动无反应，`handleMouseDown` 根本没被调用。

**原因**：OrbitControls 在构造时会注册自己的 `mousedown` 监听器，并调用 `event.preventDefault()`，消费了事件，导致我们的监听器收不到 mousedown。

#### 尝试二：设置 `mouseButtons.LEFT = null`

**方案**：把 OrbitControls 的左键映射设为 null，希望它不再处理左键 mousedown。

```javascript
this.controls.mouseButtons = {
    LEFT: null,
    MIDDLE: THREE.MOUSE.DOLLY,
    RIGHT: THREE.MOUSE.ROTATE
}
```

**结果**：❌ 仍然无效。`LEFT: null` 只让 OrbitControls 不执行旋转动作，但它的 mousedown 监听器依然存在，仍会 `preventDefault` 阻止事件传播。

#### 尝试三：capture 阶段 + stopImmediatePropagation

**方案**：在 canvas 上用 capture 阶段（第三个参数 `true`）注册监听器，先于 OrbitControls 的 bubble 阶段监听器执行，并调用 `stopImmediatePropagation()` 阻止后续监听器。

```javascript
this._canvasMouseDownCapture = (event) => {
    if (event.button === 0) {
        event.stopImmediatePropagation()
        this.handleMouseDown(event)
    }
}
canvasEl.addEventListener('mousedown', this._canvasMouseDownCapture, true)
```

**结果**：❌ 仍然无效。日志显示 canvas 上的 mousedown 完全不触发，只有 click 事件能触发。

**原因**：经深入分析，OrbitControls 某些版本在绑定时就可能在内部用 capture 或在更早阶段处理事件，`stopImmediatePropagation` 无法保证先于它执行。这个方案在不同 OrbitControls 版本上行为不一致，不可靠。

#### 尝试四（最终方案）：OrbitControls 物理隔离——独立旋转控制层

**方案**：彻底放弃让 OrbitControls 和我们的拖拽逻辑共享同一个 DOM 元素。新建一个**独立的透明 div 层** `rotate-overlay`，让 OrbitControls 绑定到这个 div，canvas 只负责渲染，鼠标事件完全由我们自己处理。

**DOM 结构**：

```
model-stage (Vue @mousedown 绑定，处理控制点拖拽)
├── model-container
│   └── canvas (Three.js 渲染，wheel 绑定用于缩放)
├── rotate-overlay (OrbitControls 绑定到这里)
│   └── 默认 pointer-events: none，事件穿透
│       freeRotate 模式下 pointer-events: auto，接收旋转事件
└── stage-hint
```

**关键代码**：

模板层：
```vue
<div class="model-stage" ref="stage"
    @mousedown="onStageMouseDown"
    @mousemove="onStageMouseMove"
    @mouseup="onStageMouseUp"
>
    <div class="model-container" ref="modelContainer"></div>
    <!-- 独立的旋转控制层：OrbitControls 绑定到此 div，不干扰 canvas -->
    <div class="rotate-overlay" ref="rotateOverlay"></div>
</div>
```

初始化时 OrbitControls 绑定到 overlay：
```javascript
const rotateOverlayEl = this.$refs.rotateOverlay
this.controls = new OrbitControls(this.camera, rotateOverlayEl || this.renderer.domElement)
this.controls.enableRotate = false   // 默认不启用旋转
```

CSS 让 overlay 默认穿透事件：
```less
.rotate-overlay {
    position: absolute;
    top: 0; left: 0;
    width: 100%; height: 100%;
    pointer-events: none;   /* 关键：默认事件穿透 */
    z-index: 5;
}
```

切换旋转模式时动态切换 pointer-events：
```javascript
toggleRotate() {
    this.freeRotate = !this.freeRotate
    if (this.controls) {
        this.controls.enableRotate = this.freeRotate
    }
    // freeRotate 模式下激活 overlay 接收事件
    if (this.$refs.rotateOverlay) {
        this.$refs.rotateOverlay.style.pointerEvents = this.freeRotate ? 'auto' : 'none'
    }
}
```

**结果**：✅ 成功。OrbitControls 的事件监听器在 overlay div 上，与 canvas 物理隔离，互不干扰。

### 拖动与指标联动的完整技术实现

事件流打通后，核心拖动逻辑如下：

#### Step 1: 鼠标按下——射线检测命中控制点

```javascript
handleMouseDown(event) {
    // 计算标准化设备坐标 (NDC)
    const rect = this.renderer.domElement.getBoundingClientRect()
    this.mouse.x = ((event.clientX - rect.left) / rect.width) * 2 - 1
    this.mouse.y = -((event.clientY - rect.top) / rect.height) * 2 + 1

    this.raycaster.setFromCamera(this.mouse, this.camera)

    // 收集所有可拖动控制点（role === 'move'）
    const controlMeshes = []
    this.controlGroups.forEach((group) => {
        group.children.forEach((child) => {
            if (child.isMesh && child.userData.role === 'move') {
                controlMeshes.push(child)
            }
        })
    })

    // 射线检测
    const intersects = this.raycaster.intersectObjects(controlMeshes)

    if (intersects.length > 0) {
        this.draggedObject = intersects[0].object
        this.draggedPoint = this.draggedObject.userData
        this.controls.enabled = false   // 拖动时禁用控制器

        // 设置拖拽平面：过控制点、面向相机
        const worldPosition = new THREE.Vector3()
        this.draggedObject.getWorldPosition(worldPosition)
        this.dragPlane.position.copy(worldPosition)
        this.dragPlane.lookAt(this.camera.position)

        // 记录拖拽偏移量，避免控制点跳变
        const planeIntersects = this.raycaster.intersectObject(this.dragPlane)
        if (planeIntersects.length > 0) {
            this.dragOffset.copy(planeIntersects[0].point).sub(worldPosition)
        }
    }
}
```

**关键技术点**：
- **Raycaster 射线检测**：从相机位置向鼠标点击方向发射射线，检测命中哪些 3D 物体
- **dragPlane 拖拽平面**：一个过控制点位置、面向相机的不可见平面，用于将 2D 鼠标移动映射到 3D 空间
- **dragOffset 偏移量**：记录鼠标点击点与控制点中心的偏差，拖动时扣除这个偏差，避免控制点瞬间跳到鼠标位置

**dragPlane 材质的坑**：最初用 `visible: false`，结果 Raycaster 直接跳过该 Mesh，拖动完全失效。必须用 `visible: true, transparent: true, opacity: 0`：

```javascript
this.dragPlane = new THREE.Mesh(
    new THREE.PlaneGeometry(20, 20),
    new THREE.MeshBasicMaterial({
        visible: true,        // 必须 true，否则 Raycaster 跳过
        transparent: true,
        opacity: 0,           // 视觉不可见
        side: THREE.DoubleSide,
        depthWrite: false
    })
)
```

#### Step 2: 鼠标移动——球面约束移动

```javascript
moveControlPoint(newPoint) {
    const group = this.controlGroups.find(
        (g) => g.userData.metricKey === this.draggedPoint.metricKey
    )
    const points = group.children.filter((child) => child.isMesh)
    const currentPoint = points[this.draggedPoint.pointIndex]

    // 找到锚点（pivot 或 center）
    let pivotPoint = null
    let centerPoint = null
    points.forEach((p) => {
        if (p.userData.role === 'pivot') pivotPoint = p
        if (p.userData.role === 'center') centerPoint = p
    })
    const rotateCenter = centerPoint || pivotPoint

    // 球面约束：保持到锚点的距离不变，只改变方向
    if (rotateCenter) {
        const center = rotateCenter.position
        const radius = center.distanceTo(currentPoint.position)
        if (radius > 0.001) {
            const direction = newPoint.clone().sub(center).normalize()
            currentPoint.position.copy(center.clone().add(direction.multiplyScalar(radius)))
        }
    } else {
        currentPoint.position.copy(newPoint)
    }

    // 更新连线
    const line = group.children.find((child) => child.isLine)
    if (line) {
        const positions = points.map((p) => p.position.clone())
        this.updateLineGeometry(line.geometry, positions)
        line.geometry.attributes.position.needsUpdate = true
    }

    // 计算指标变化
    this.calculateMetricDelta(group)
}
```

**球面约束的物理意义**：模拟关节运动。例如膝盖控制点拖动时，以髋关节为圆心、大腿长为半径，控制点只能在这个球面上移动，符合人体关节运动学。

#### Step 3: 指标实时计算

```javascript
calculateMetricDelta(group) {
    const metricKey = group.userData.metricKey
    const points = group.children.filter((child) => child.isMesh)
    const initial = this.initialControls.find((item) => item.key === metricKey)

    let delta = 0

    if (points.length === 2) {
        // 两点指标：计算向量角度变化（如肩平衡、膝超伸）
        const currentVector = new THREE.Vector3().subVectors(points[1].position, points[0].position)
        const initialVector = new THREE.Vector3().subVectors(initial.positions[1], initial.positions[0])
        const angle = currentVector.angleTo(initialVector)
        delta = THREE.MathUtils.radToDeg(angle)

        // 用叉积判断方向（正负）
        const cross = new THREE.Vector3().crossVectors(initialVector, currentVector)
        if (cross.z < 0) delta = -delta
    } else if (points.length === 3) {
        // 三点指标：计算夹角变化（如膝内外翻）
        const currentAngle = this.calculateThreePointAngle(
            points[0].position, points[1].position, points[2].position
        )
        const initialAngle = this.calculateThreePointAngle(
            initial.positions[0], initial.positions[1], initial.positions[2]
        )
        delta = currentAngle - initialAngle
    }

    // 触发父组件更新指标
    this.$emit('adjust-metric', {
        key: metricKey,
        delta: Math.round(delta * 10) / 10
    })
}
```

**两种指标算法**：
- **两点指标**（肩平衡、膝超伸）：计算当前向量与初始向量的夹角，用叉积 z 分量判断旋转方向
- **三点指标**（膝内外翻）：计算三点形成的夹角变化

### 最终效果

- 红色控制点清晰显示在模型对应解剖位置
- 左键按住红色控制点拖动，控制点沿球面平滑移动，连线实时跟随
- 拖动过程中，左侧指标面板数值实时更新
- 点击「自由旋转」按钮后，左键/右键拖动可旋转模型，再点击退出旋转模式恢复拖点

| 尝试 | 方案 | 结果 | 失败原因 |
|------|------|------|----------|
| 1 | canvas 上 addEventListener | ❌ | OrbitControls 消费 mousedown |

## 5. 控制点自动贴合真实模型比例

### 问题是什么

不同 OBJ 模型的坐标范围差异极大（体态模型高度 1726mm，足压模型高度 224mm）。控制点位置不能写死，必须**根据模型实际尺寸按比例计算**，否则会出现：
- 控制点偏离模型（在模型外悬浮）
- 控制点挤成一团（多个点重叠）
- 控制点在模型内部不可见

### 迭代尝试

#### 尝试一：用模型缩放后的世界坐标包围盒计算控制点

**方案**：`centerModel()` 后，用 `new THREE.Box3().setFromObject(this.model)` 取世界包围盒，按比例计算控制点位置。

**结果**：❌ 控制点位置错误，跑到了视野外。

**原因**：`setFromObject` 取的是**世界坐标**（已经过缩放和位移）。但控制点定义中的坐标是**模型本地坐标**，后续 `localToModelWorld()` 又做了一次 `× scale + position` 转换，导致坐标被**二次缩放**。

#### 尝试二（最终方案）：保存原始本地包围盒 + 坐标转换

**方案**：在 `centerModel()` **之前**记录模型原始本地坐标包围盒 `originalBox`，控制点基于原始本地坐标定义，再经 `localToModelWorld()` 正确转换到世界坐标。

```javascript
// loadModel 中，在 centerModel 之前
const rawBox = new THREE.Box3().setFromObject(object)
const size = rawBox.getSize(new THREE.Vector3())
const center = rawBox.getCenter(new THREE.Vector3())
this.originalBox = Object.freeze({
    min: Object.freeze(rawBox.min.clone()),
    max: Object.freeze(rawBox.max.clone()),
    size: Object.freeze(size),
    center: Object.freeze(center)
})
// ...之后才调用 centerModel(object)
```

**Vue 响应式的坑**：最初 `originalBox` 声明在 `data()` 中，被 Vue 响应式系统递归包装了 `THREE.Vector3`（日志显示 `Vector3 {__ob__: Observer}`），响应式 getter/setter 破坏了 Three.js 对 Vector3 的内部访问。

**修复**：从 `data()` 移除，在 `created()` 中初始化为非响应式属性，并用 `Object.freeze` 双重保险：

```javascript
created() {
    this.originalBox = null   // 非响应式，避免 Vue 包装 THREE.Vector3
}
```

## 7. 医生审核页红色控制点不显示问题排查

### 问题是什么

医生审核页加载模型后，红色控制点完全不显示，用户无法进行点位调整。这是开发过程中遇到的最棘手的可见性 bug，涉及多个隐藏问题。

### 排查过程与迭代修复

#### 问题一：Vue 响应式包装 THREE.Vector3

**现象**：日志输出 `原始 size= Vector3 {__ob__: Observer}`，而非纯数值。

**根因**：`originalBox` 声明在 `data()` 中，Vue 递归地把 `THREE.Vector3` 包装成响应式对象。响应式 getter/setter 破坏了 Three.js 内部对 Vector3 属性的直接访问，导致后续坐标计算异常。

**修复**：
```javascript
// 从 data() 移除 originalBox
// 在 created() 中初始化为非响应式属性
created() {
    this.originalBox = null
}
// 赋值时用 Object.freeze 双重保险
this.originalBox = Object.freeze({
    min: Object.freeze(rawBox.min.clone()),
    max: Object.freeze(rawBox.max.clone()),
    size: Object.freeze(size),
    center: Object.freeze(center)
})
```

**教训**：Three.js 的对象（Vector3、Matrix4、Color 等）不应放进 Vue 的 `data()`，否则响应式包装会破坏其内部逻辑。一律用非响应式属性（`this.xxx =` 在 created/methods 中直接赋值）。

#### 问题二：足压模型控制点挤成一团

**现象**：日志显示 `leftWidth[1] 世界 = (-0.04, 0, 0)`，`rightWidth[0] 世界 = (0.04, 0, 0)`，左右脚的宽度控制点交叉重叠在原点附近。

**根因**：`footWidth = size.x * 0.18 = 308 * 0.18 ≈ 55`，而 `size.x` 是**两只脚总宽度**。`leftFootX + footWidth = -60.6 + 55 = -5.2` 跨过中心线，与右脚的 `rightFootX - footWidth = 62.8 - 55 = 7.8` 重叠。

**修复**：改用左右脚间距估算单只脚宽度：

```javascript
// 之前：footWidth = size.x * 0.18  ← 用两只脚总宽度，太大
const footGap = rightFootX - leftFootX
const footWidth = Math.min(footGap * 0.4, size.x * 0.1)
```

#### 问题三：控制点在模型内部不可见

**现象**：体态模型控制点世界坐标 `(-0.266, 0.84, 0)`，而模型 z 范围 `[-0.266, 0.266]`，控制点 z=0 在模型几何体内部，被模型遮挡。

**根因**：
1. 控制点半径 0.09 相对模型高度 3 单位偏小
2. `depthTest` 默认 true，控制点被前方模型几何体遮挡

**修复**：
```javascript
// 1. 控制点半径自适应
let controlRadius = 0.09
if (this.model) {
    const worldBox = new THREE.Box3().setFromObject(this.model)
    const worldSize = worldBox.getSize(new THREE.Vector3())
    controlRadius = Math.max(0.08, worldSize.length() * 0.035)
}

// 2. depthTest:false + renderOrder:999 确保始终绘制在模型之上
const material = new THREE.MeshBasicMaterial({
    color: 0xef4444,
    depthTest: false,        // 关键：不进行深度测试
    transparent: true,
    opacity: 0.95
})
sphere.renderOrder = 999     // 关键：最后绘制
```

**技术原理**：`depthTest: false` 让控制点不参与深度缓冲比较，`renderOrder: 999` 确保它在所有模型几何体之后绘制，从而始终显示在最上层。

#### 问题四：拖动时控制点无反应（事件流问题）

这部分已在第 4 节详述，核心是 OrbitControls 拦截 mousedown 事件，最终通过「独立 rotate-overlay 物理隔离」方案解决。

### 排查方法论

本次排查采用**日志驱动的科学调试法**：

1. **加日志**：在关键节点（initThree、loadModel、rebuildControls、handleMouseDown）插入 `console.log`
2. **看数值**：根据日志输出的实际坐标值判断哪一步计算错误
3. **定位根因**：例如 `Vector3 {__ob__: Observer}` 直接暴露 Vue 响应式问题
4. **针对性修复**：不盲目改代码，每一步修复都对应明确的日志证据

关键诊断日志示例：

### 迭代尝试

#### 尝试一：仅更新内存中的 reportRecord

**原始代码**（[ModelImport/Index.vue](file:///c:/Users/Administrator/work/ve730-ve760/ve730-cms-frontend/src/pages/model-import/Index.vue)）：


**结果**：❌ PDF 能正确显示（因为 PDF 是从当前页面的 DOM 直接截图生成，读的是内存中的 `reportRecord`），但从报告列表查看时丢失。

```
  MedicalReportViewer → $emit('update:record') → updateReportRecord

  → 从 storage 读取 → doctorAdvice 仍是初始空字符串 ❌
```

**结果**：⚠️ 部分生效。在 localStorage 版本下，`addReport` 是先 `getReports()` 读全量数组、`findIndex` 找到记录、合并字段、再 `saveReports` 全量写回。这个方案能工作，但有两个隐患：

1. **全量读写性能差**：每次编辑医生建议都要读取整个报告数组、序列化、写回。
2. **并发覆盖风险**：如果用户在 A 标签编辑、B 标签同时操作，全量读-改-写会互相覆盖。

而且当时 localStorage 还无法存储模型 Blob（见第 11 节），所以这个方案在重构 indexedDB 时被一并重写。

#### 尝试三（最终方案）：indexedDB 合并语义的 addReport + 两处同步持久化

**方案**：重构 indexedDB 后，`addReport` 改为「读取单条 → 合并 → 写回单条」的合并语义（而非全量读-改-写）。同时在两个入口（生成报告页 `ModelImport/Index.vue` 和报告查看页 `report/Index.vue`）都实现持久化。

**indexedDB 版 addReport 合并语义**：

```javascript
// src/utils/reportStorage.js
export async function addReport(report) {
    await tx(REPORT_STORE, (store) => {
        return new Promise((resolve, reject) => {
            // 先读取已有记录
            const getReq = store.get(report.scanId)
            getReq.onsuccess = () => {
                const existing = getReq.result || {}
                const merged = { ...existing, ...report }   // 浅合并
                const putReq = store.put(merged)
                putReq.onsuccess = () => resolve()
                putReq.onerror = () => reject(putReq.error)
            }
            getReq.onerror = () => reject(getReq.error)
        })
    }, 'readwrite')
    notifyChange()
}
```

**关键技术点**：
- **合并而非覆盖**：`store.put()` 默认是整体覆盖。如果 `updateReportRecord` 只传了 `{scanId, doctorAdvice, ...}` 三个字段，直接 put 会丢失 `metrics`、`fileName` 等其他字段。因此必须先 `get` 再 `{...existing, ...report}` 合并，最后 `put` 合并后的完整对象。
- **单条读写**：相比 localStorage 的全量数组读-改-写，indexedDB 的 `get(scanId)` + `put(merged)` 只操作单条记录，性能更好，并发风险更低。
- **事务保证**：get 和 put 在同一个 `readwrite` 事务内，事务未完成前其他事务无法插入，保证合并的原子性。

**入口 1：生成报告页持久化**（[ModelImport/Index.vue](file:///c:/Users/Administrator/work/ve730-ve760/ve730-cms-frontend/src/pages/model-import/Index.vue)）：

## 11. 本地存储从 localStorage 重构为 indexedDB

### 问题是什么

原 `reportStorage.js` 基于 localStorage 实现，随着功能演进暴露出三个根本性问题：

1. **无法存储二进制模型文件**：OBJ 模型是二进制 Blob，localStorage 只能存 String。原方案用 `URL.createObjectURL(file)` 生成的 object URL 会随页面会话失效，导致从报告列表查看报告时模型无法显示（只能显示 SVG 占位图）。
2. **容量限制**：localStorage 上限 5-10MB，几个 OBJ 模型就可能撑爆。
3. **同步阻塞**：localStorage 的 `getItem/setItem` 是同步 API，大数据量序列化/反序列化会阻塞主线程。

需求要求「在报告列表查看报告时展示真实模型」，这就必须把模型 Blob 持久化下来。localStorage 无法胜任，需要重构为 indexedDB。

### 存储方案评估

| 维度 | localStorage | indexedDB |
|------|--------------|-----------|
| 二进制 Blob 存储 | ❌ 仅支持 String，需 base64 膨胀 33% | ✅ 原生支持 Blob/File |
| 存储容量 | 5-10MB | 50MB+（通常数百 MB） |
| API 模型 | 同步阻塞主线程 | 异步非阻塞 |
| 查询能力 | 全量遍历 | 支持索引、游标 |
| 事务支持 | 无 | 有（readwrite/readonly） |
| 适用场景 | 少量配置项、token | 结构化数据 + 二进制文件 |

**结论**：本项目需存储 OBJ 模型 Blob（可达数 MB）+ 报告元数据，indexedDB 是更规范、更优雅的方案。

### 迭代尝试

#### 尝试一：localStorage + base64 编码 Blob

**方案**：用 `FileReader.readAsDataURL` 把 Blob 转 base64 字符串存进 localStorage，查看时 `fetch(dataURL).then(r => r.blob())` 还原。

**结果**：❌ 否决。

**原因**：
1. base64 膨胀 33%，3MB 模型变成 4MB 字符串，几个报告就撑爆 5MB 上限。
2. 序列化/反序列化全程同步阻塞主线程，大模型会导致页面卡死数百毫秒。
3. `JSON.stringify` 一个含大段 base64 的对象极其缓慢。

这个方案在技术评审阶段就被否决，没有实际编码。

#### 尝试二：保留 localStorage 存报告元数据，模型 Blob 不持久化

**方案**：报告元数据（scanId、metrics、doctorAdvice 等）仍存 localStorage，模型 Blob 不存。从报告列表查看时，`modelUrl` 留空，ReportModelViewer 显示 SVG fallback。

**结果**：⚠️ 功能降级。报告能查看，但模型区域是 SVG 简笔画，与生成报告页的真实模型体验严重不一致。用户明确反馈「期望展示真实模型」。

**原因**：这是妥协方案，没有真正解决问题。模型是报告的核心视觉内容，SVG 占位图无法满足医疗评估的专业性要求。

#### 尝试三（最终方案）：全面重构为 indexedDB，双 store 设计

**方案**：用 indexedDB 建立两个 object store——`reports` 存报告元数据（JSON），`models` 存模型 Blob 文件。所有 API 改为 async，跨标签同步改用 BroadcastChannel。

**数据库设计**：

```javascript
const DB_NAME = 've760_model_import_db'
const DB_VERSION = 1
// reports store：报告元数据，keyPath 为 scanId
// models store：模型 Blob 文件，keyPath 为 scanId
```

`openDB` 在 `onupgradeneeded` 中创建两个 store：

```javascript
function openDB() {
    if (dbPromise) return dbPromise
    dbPromise = new Promise((resolve, reject) => {
        const request = indexedDB.open(DB_NAME, DB_VERSION)
        request.onupgradeneeded = (event) => {
            const db = event.target.result
            if (!db.objectStoreNames.contains(REPORT_STORE)) {
                db.createObjectStore(REPORT_STORE, { keyPath: 'scanId' })
            }
            if (!db.objectStoreNames.contains(MODEL_STORE)) {
                db.createObjectStore(MODEL_STORE, { keyPath: 'scanId' })
            }
        }
        request.onsuccess = () => resolve(request.result)
        request.onerror = () => reject(request.error)
    })
    return dbPromise
}
```

**事务封装**：抽象出 `tx(storeName, fn, mode)` 统一处理事务生命周期：

```javascript
async function tx(storeName, fn, mode = 'readonly') {
    const db = await openDB()
    return new Promise((resolve, reject) => {
        const transaction = db.transaction(storeName, mode)
        const store = transaction.objectStore(storeName)
        let result
        Promise.resolve(fn(store))
            .then((r) => { result = r })
            .catch(reject)
        transaction.oncomplete = () => resolve(result)
        transaction.onerror = () => reject(transaction.error)
        transaction.onabort = () => reject(transaction.error)
    })
}
```

```javascript
// generateReviewReport 生成报告时持久化模型
await addReport(reportRecord)
if (this.selectedFile) {
    await saveModel(scanId, this.selectedFile, this.currentModelType, this.reviewRecord.fileName)
}
```

### 最终效果

- 报告元数据存储在 `reports` store，模型 Blob 存储在 `models` store，结构清晰
- 生成报告时模型 Blob 被持久化，从报告列表查看时通过 `getModel(scanId)` 还原 object URL，真实模型正常显示
- indexedDB 容量充足（数百 MB），不再有 5-10MB 限制
- 异步 API 不阻塞主线程，大模型读写流畅
- BroadcastChannel 实现跨标签页同步，A 标签生成报告 → B 标签列表自动刷新
- 旧 localStorage 数据首次访问时自动迁移到 indexedDB，迁移完成后清除旧 key
- `addReport` 合并语义保证局部更新不丢失其他字段（见第 10 节）

### 迁移前后对比

| 方面 | 迁移前（localStorage） | 迁移后（indexedDB） |
|------|------------------------|---------------------|
| 模型 Blob 存储 | ❌ 无法存储，URL 随页面失效 | ✅ 原生 Blob 存储 |
| 查看报告时模型 | ❌ 显示 SVG 占位图 | ✅ 显示真实 3D 模型 |
| 容量 | 5-10MB | 数百 MB |
| API 模型 | 同步阻塞 | 异步非阻塞 |
| 跨标签同步 | storage 事件 | BroadcastChannel |
| 局部更新 | 全量读-改-写 | 单条 get-merge-put |
| 数据完整性 | JSON 序列化整个数组 | 结构化对象 store |

### 风险与权衡

1. **多 ReportModelViewer 实例性能**：评估表版体态报告同时渲染 5 个 Three.js 实例，大模型下可能卡顿。这是既有架构限制，可后续优化为共享 renderer 多视图。
2. **object URL 未显式 revoke**：每次查看报告 `URL.createObjectURL` 创建对象 URL，组件销毁时 Three.js 资源已 dispose，但 object URL 本身未 `revokeObjectURL`。少量查看不影响，严格管理可在 `beforeDestroy` 中释放。
3. **迁移竞态**：多标签同时首次打开时，`migrated` 标志为模块级单例，仅首个调用执行迁移。极端情况下第二个标签可能读到迁移前空数据，但 BroadcastChannel 会触发重新加载，最终一致。

### 关键工程教训

1. **Three.js 对象不要放进 Vue data()**：响应式包装会破坏 Three.js 内部逻辑，用非响应式属性 + Object.freeze
2. **事件系统冲突用物理隔离解决**：capture/stopPropagation 不可靠，独立 DOM 层是最稳方案
3. **坐标系要明确区分**：本地坐标 vs 世界坐标，缩放前 vs 缩放后，不能混用
4. **depthTest:false + renderOrder 解决遮挡**：UI 层元素（控制点、连线）需要始终可见时用此组合
5. **日志驱动调试**：复杂 3D 交互问题靠静态分析难以定位，关键节点日志是唯一可靠手段
6. **二进制数据用 indexedDB 而非 localStorage**：Blob/File 必须用 indexedDB 原生存储，base64 编码到 localStorage 会膨胀 33% 且阻塞主线程
7. **局部更新用合并语义而非整体覆盖**：indexedDB 的 `store.put()` 是整体覆盖，更新部分字段时必须先 get 再 `{...existing, ...patch}` 合并，否则丢失其他字段
8. **数据流要形成闭环**：编辑入口（updateRecord）和读取入口（loadReport）必须指向同一个持久化存储，否则会出现「编辑生效但查看丢失」的现象
9. **视角与模型类型是正交维度**：ReportModelViewer 的 pose（front/back/left/right/top）与 modelType（body/foot）独立控制，不能用 modelType 复用视角逻辑
10. **跨标签同步随存储方案升级**：localStorage 用 storage 事件，indexedDB 必须改用 BroadcastChannel（indexedDB 变化不触发 storage 事件）
